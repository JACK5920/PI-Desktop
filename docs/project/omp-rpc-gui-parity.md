# oh-my-pi RPC-UI capability parity

Initial baseline: oh-my-pi `18.20.0`, source revision `57263720c818ab3baaeb74bf415b03592b806ae0`, official `docs/rpc.md` and generated `rpc-wire` command/event schemas. The last full command/frame parity audit is `18.22.2`; later targeted release audits are recorded separately and do not imply a complete wire audit. This is a public RPC-UI parity audit, **not** a claim that PI reproduces the terminal TUI pixel-for-pixel.

## Coverage contract

At the last full pinned v18.22.2 upstream wire schema, all 74 declared RPC commands and every documented outbound frame are accounted for: 71 commands are available through the chat-session allowlist; `negotiate_protocol` is performed internally by the process runtime; and `set_host_tools` plus `set_host_uri_schemes` are registered internally with a project-scoped read/write/edit surface routed through Host authorization (they are not renderer-invocable). The managed engine supports `set_cache_warming`; older `18.20.0` processes return `Unknown command`, which the UI reports instead of pretending the setting changed. The v18.22.2 command/type and RPC-reference sources are byte-identical to v18.22.1.

## This delivery

- Make every session-scoped OMP GUI command lazily connect its validated native RPC session before dispatch. This covers restored conversations where session controls, native slash commands, prediction, voice, or subagent views can be the first surface opened, instead of requiring a prior prompt/model-picker attach.
- Expose the remaining public session/audio/subagent/side-question RPC commands through the session-scoped IPC allowlist; settings RPC remains separately narrowed.
- Enable the official `set_ask_dialog` opt-in for chat RPC sessions because the GUI supports OMP's structured question UI; verify the installed binary returns the enabled state.
- Add OMP-native live voice start/stop/mute and live input/output meters; display native state/transcript events; append dictation output without replacing the user's existing draft; add a renderer WebRTC peer path with an owner-bound microphone lease.
- Add an OMP-native available-command picker backed by `get_available_commands` and `available_commands_update`; selecting a command edits the draft only.
- Persist builtin slash-command output as a completed conversation row after stripping ANSI/terminal control sequences; refresh model/thinking state on native configuration events and mirror OMP-generated title changes to the matching PI conversation.
- Refresh the OMP-owned goal/todo snapshot after `todo_auto_clear` by reading `get_state` instead of inferring state from notification shape.
- Add OMP `predict_word` ghost text with debouncing, end-of-draft/caret validation, Tab acceptance, and acceptance/dismissal feedback; prediction failures never interrupt typing.
- Keep the selected OMP subagent transcript live: refresh its registry status on events, append only new byte-cursor messages, coalesce overlapping refreshes, and clear stale transcript state when selection/session changes.
- Render OMP subagent text, tool calls, reasoning blocks, and bounded inline raster-image previews as structured transcript rows instead of dropping non-text content; keep reasoning collapsed by default and reject oversized or non-raster inline payloads from preview.
- Present OMP BTW history as selectable topics with status/timestamps, full follow-up turns and record-scoped cancel/reply; prevent submissions that the native one-question-at-a-time contract would reject.
- Add a separate OMP Goal/todo panel backed only by OMP `goal`/`get_state`/`get_tree` RPC: create with optional token budget, pause/resume/drop, show usage, and edit core fields plus `details`/`notes` without losing unknown JSON extensions. Because OMP 18.20.2's in-memory TodoTracker clone exposes only core fields, the GUI rehydrates extensions from OMP's native active-branch `user_todo_edit` and todo-tool entries, verifies the submitted full snapshot exists in that journal, and does not maintain a PI shadow store.
- Add a separate OMP session-control panel backed only by OMP `get_state` and native commands: inspect and remove/promote displayable queue items, change OMP's session-only queue/interruption/compaction/retry settings, compact, abort retry, run/cancel native RPC bash, rename/export the OMP session, and request a native handoff. Preserve event-driven queue snapshots and exact-text RPC removal semantics; do not read PI queue state or route OMP shell output through PI tool approvals.
- Show native `get_session_lease` status for the active OMP session; report unknown when OMP cannot verify it rather than interpreting failure as free.
- Add bounded inspection of OMP's `get_tree` response; cap rendering at 300 entries and mark the current OMP leaf. Tree selection is read-only browsing. Use native `fork` to create a distinct PI conversation only after the new OMP file is validated, both PI↔OMP mappings are atomically persisted, the source is restored to its complete parent history, and restart verification passes. Do not translate OMP's transient `navigate_tree` cursor into a permanent PI transcript rewrite. Show `get_branch_messages` as OMP's forkable-user-message list, not as a branch transcript preview.
- Expose OMP's native `get_session_stats` values in the session panel, preserving optional/unknown context values instead of fabricating usage.
- Probe documented-but-optional session commands in the isolated binary smoke and report capability availability; do not show GUI actions when this installed binary answers `Unknown command`.
- Map the busy-composer steer/follow-up choices to OMP-native dispatch: steer uses `steer`; normal in-run send is explicitly `prompt` with `streamingBehavior: "followUp"`, persisted in PI's mirror only after OMP acceptance, and never placed into PI's independent queue.
- Add session-scoped OMP side-question history, follow-up/cancel actions and event-driven refresh; add subagent transcript byte-cursor reads alongside steer/cancel and event-driven status refresh.
- Give cold native dictation/model initialization the upstream-compatible long RPC deadline.

## Acceptance gates before claiming full parity

1. Test voice and dictation on each supported OS with microphone permission denied/granted, start cancellation, process close, transcription failure, WebRTC peer disconnect, and no duplicate draft insertion.
2. Verify OMP subagent lifecycle/stream behavior on supported platforms after the renderer-controlled subscription lifecycle.
3. Verify BTW topic history and follow-up with a real configured OMP provider; keep it distinct from PI Side Chat.
4. Verify the WebRTC peer path with real supported microphones/speakers and provider credentials; exercise permission denial, peer disconnect and app shutdown.
5. Verify all official `RpcCommand` names and every unsolicited frame against this table in automated tests on each OMP update; report TUI-only and deliberately unregistered host channels explicitly.
6. Run real-model tests only with user-configured OMP credentials; isolated fake/local tests do not prove provider behavior.

## Explicit parity boundary

- Historical state before durable-fork implementation: in-place tree navigation modified the current transcript mirror, and fork remained disabled.
- The OMP `get_state` TodoTracker snapshot can still omit `details`, `notes`, or other extension fields; the GUI obtains the complete durable snapshot from the active branch's native OMP session entries and verifies it again after `set_todos`. It does not store a parallel PI Todo sidecar. The UI remains non-editable only when the native history cannot be verified, the snapshot is malformed, or it exceeds the explicit 1 MiB safety bound; it explains that state rather than silently discarding fields.
- “All RPC parity” means every command and unsolicited frame is accounted for and every safely representable public interaction is either GUI-integrated or explicitly rejected/disabled with a reason. It does not mean every RPC call is meaningful in a GUI, nor that TUI-only terminal rendering, key handling, or component factories can be reproduced. Real model-provider and device acceptance remain separate from isolated protocol/build tests.

## Durable native fork (2026-11-15)

- The active session-tree UI uses tree rows for read-only browsing. Selecting a user or assistant message and choosing “fork from entry” creates a separate PI session; it does not truncate, rewrite, or change the active parent conversation.
- The IPC boundary independently verifies that the selected entry currently exists in OMP's session tree and is a user/assistant message before creating the target PI conversation. This avoids trusting renderer-provided role/entry data or creating empty sessions for stale selections.
- The runtime verifies OMP's reported fork session file is a distinct file inside the managed session store, normalizes the complete child snapshot, atomically persists the parent/child PI-to-OMP file mappings, restores the parent native file and returns the complete parent snapshot. The IPC layer persists that parent snapshot and the fork snapshot to their respective PI conversations; a failure before runtime commit compensates the native switch and removes the new mapping/session, while a Host mirror-write failure after commit retains the paired recovery journal and retries the canonical snapshots rather than deleting the child.
- In-memory tree navigation is not exposed as permanent history navigation: isolated tests showed that reopening the session file restores the full stored parent despite a shorter transient tree view. Windows path checks resolve short/long path aliases before validating parent/child identity.
- Real OMP `18.20.0` and SHA-verified `18.20.2` isolated suites verify fork contents, full parent preservation, and both durable mappings after stopping and recreating the RPC runtime. On `18.20.2`, `get_login_providers` also exposes the new `antigravity-cli` provider through the existing data-driven GUI catalog; actual CLI installation, Google sign-in and model call still require the provider's native setup and account.
- Upstream `18.20.2` still clones Todo phases/tasks using only `name`, `content` and `status`; `details`/`notes` are not preserved by `set_todos`. PI therefore retains the lossless-shape edit gate and does not keep shadow Todo state or patch the official binary. The latest release did not remove this boundary.

## OMP 19.0.0 local spill-reference checkpoint (2026-11-19)

- OMP v19 emits session-owned large-output spills as `local://N.log` (optionally followed by a read selector). The normal local root is the `local` directory beside the session JSONL's artifact directory; on Windows, OMP switches to `%TEMP%\\omp-local\\<safe-session-id>` when the resolved local root reaches 180 characters.

## Same-chat native prompt editing (2026-11-20)

- OMP user-message **Edit** and assistant-turn **Regenerate** stay in the current PI chat and current OMP native session; they do not create another PI sidebar conversation. OMP keeps the original prompt/response in its tree and records the replacement prompt as a sibling. The active transcript then follows the replacement branch.
- Main-process validation resolves the renderer's PI message ID against the current OMP `get_messages` snapshot and `get_tree`, and only accepts a user entry on the active branch. A stale entry refreshes the PI mirror from OMP and returns `OMP_HISTORY_STALE`; it does not append or send stale text.
- The guarded sequence is: reject busy/pending turns; navigate the native cursor to the selected prompt's parent; verify the resulting leaf and canonical branch snapshot; replace the PI mirror; persist the edited user row; then submit the OMP-native prompt. If a Host mirror acknowledgement or user-row persistence fails, the runtime restores the original native leaf and canonical PI snapshot before releasing the operation lock. An ambiguous RPC error after prompt submission is checked against native state/tree/messages to avoid asking the user to resend a prompt OMP already accepted.
- When the edit keeps the original inline images, the runtime converts OMP's normalized `data:` image references back to the raw base64 shape required by the native RPC `prompt` command. Image-only prompts remain valid; an empty edit with no retained/new image is rejected before moving the native cursor.
- The edit request carries the original PI message ID only as a validated native-tree target; it does not use PI's `truncateFromMessageId` mutation. Ordinary PI editing, deletion, revisions and generic forks are unchanged. OMP does not expose arbitrary deletion of old native entries through this UI.
